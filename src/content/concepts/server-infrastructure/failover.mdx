## The problem

A Primary stops responding. “Make the Replica Primary” is not enough.

If the old Primary can still write after a new node is promoted, the system can have two writers. If the Replica is behind, promotion can expose a worse recovery point.

## Mental model

Treat failover as an ordered safety protocol:

```text
detect
  ↓
fence old writer
  ↓
verify candidate freshness
  ↓
promote
  ↓
move stable endpoint
  ↓
retry
```

The lesson uses one concrete replication position: both nodes are at **LSN 120** before failure.

<Callout title="Fence before promote">
  Failure detection tells you that the old writer is not responding from one observer's perspective. Fencing is what prevents that writer from later returning and accepting conflicting writes.
</Callout>

## Practical example

Fencing can be implemented in many ways: power control, storage lease, consensus membership, cloud API isolation, or a strongly controlled lock/epoch mechanism. The exact mechanism depends on the system.

Freshness also needs an explicit rule. In PostgreSQL, WAL positions and replication state can help determine how far a standby has replayed. A production failover system needs a policy for acceptable data-loss risk, not merely “Replica process is running.”

Stable endpoints matter because application clients should not need a deploy just because the database role moved.

## Failure modes and trade-offs

- **Promote before fencing:** possible split-brain.
- **False failure detection:** unnecessary role change.
- **Stale candidate:** unacceptable RPO or missing committed data.
- **Endpoint convergence is slow:** clients keep dialing the old location.
- **Retry is unsafe:** ambiguous writes can be duplicated if the operation is not designed for retries.

Record the detection time, fencing result, replication position, promotion time and endpoint switch in the incident timeline.

## Takeaway

Failover is a **sequence**, not a color change in a diagram. Detect → fence → verify freshness → promote → reroute → retry. Safety depends on the order.
