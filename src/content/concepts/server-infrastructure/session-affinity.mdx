## The problem

User A has a shopping cart stored only in App 1 memory. A load balancer can keep sending that user back to App 1, but that does not make the cart durable.

Affinity solves a **routing locality** problem. It can also create a new coupling between one user and one process.

## Mental model

First request:

```http
GET /cart
Cookie: (none)
```

The balancer chooses App 1 and can return:

```http
Set-Cookie: route=app1
```

Next request:

```http
GET /cart
Cookie: route=app1
```

The load balancer selects App 1 again, where local session A contains `cart=3`.

<Callout title="A routing cookie is not durable storage">
  If App 1 disappears, the cookie can still exist while the process-local session is gone. Affinity preserves locality only while the target remains usable.
</Callout>

## Practical example

Kubernetes Services can use `sessionAffinity: ClientIP`, which is based on client IP rather than a cookie. Reverse proxies and application gateways can implement other affinity mechanisms. The exact key matters because NAT, proxies and mobile networks can change apparent client identity.

Affinity can hide load skew. App 1 might reach 90% utilization while App 2 sits at 30%. A fleet average of 60% looks fine even though one target is close to saturation.

Moving session state to a shared store is one way to decouple routing from one process. Another is to design the application to keep user state in durable backend systems and make App instances stateless. Both choices have their own latency and availability trade-offs.

## Failure modes and trade-offs

- **Hot target:** sticky users accumulate unevenly.
- **Target failure:** the affinity key still names a dead or draining target.
- **Process-local session loss:** state disappears with the instance.
- **Rebalancing is harder:** removing a target disrupts pinned users.
- **Shared session store becomes a dependency:** durability improves but a new network/storage path exists.

Measure per-instance load, affinity hit rate, session recovery failures and distribution skew.

## Takeaway

Session affinity says **“prefer the same target”**, not **“this state is safe.”** Treat routing locality, load distribution and session durability as separate design decisions.
